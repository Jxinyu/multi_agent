# 三端前端实现验收

## 实现范围

当前前端共实现 16 个实际页面，覆盖公共登录、用户端、企业端和平台管理端。13 张桌面设计图中的“安全审计与系统运行”被拆成安全、运维、模型三个独立页面，并增加只读平台配置页。

| 端 | 路由 | 页面 | 数据来源 |
| --- | --- | --- | --- |
| 公共 | `/login` | 登录与租户选择 | 开发令牌或正式 JWT/OIDC |
| 用户端 | `/app` | AI 工作台 | 本地会话状态、真实聊天接口 |
| 用户端 | `/app/chat/:threadId` | 多智能体回答 | `/api/chat` SSE 流 |
| 用户端 | `/app/search` | 企业搜索与证据 | `/api/search` 混合检索 |
| 用户端 | `/app/tasks` | 任务与追问 | `/api/tasks` 审计终态聚合 |
| 用户端 | `/app/documents` | 我的文档 | `/api/documents`、上传与入库接口 |
| 企业端 | `/enterprise` | 企业运营总览 | 租户审计、文档和依赖探针 |
| 企业端 | `/enterprise/knowledge` | 知识与解析 | 租户文档、上传和解析状态 |
| 企业端 | `/enterprise/agents` | 智能体与 MCP | 智能体枚举与 MCP 启动配置 |
| 企业端 | `/enterprise/members` | 成员与权限 | JWT 声明与审计中已观测身份 |
| 企业端 | `/enterprise/evaluation` | 评测与成本 | 版本库中的固定评测结果文件 |
| 管理端 | `/admin/tenants` | 租户与配额 | 当前 JWT 租户、审计、文档和全局限制 |
| 管理端 | `/admin/security` | 安全审计 | `/api/admin/audit-events` |
| 管理端 | `/admin/operations` | 系统运行 | 健康探针与 Worker 启动策略 |
| 管理端 | `/admin/models` | 模型与容量 | Ollama `/api/tags` |
| 管理端 | `/admin/settings` | 平台配置 | 启动配置与环境变量的脱敏只读视图 |

## 已实现动态效果

- 用户问答按 SSE 内容块流式追加，提供停止、引用、附件和终态反馈。
- 用户工作台快捷任务分批进入，输入聚焦和拖拽附件具有状态反馈。
- 搜索加载、证据选择、任务刷新、文档上传与入库进度保持稳定布局。
- 三端侧栏在移动端使用遮罩抽屉，关闭后不改变页面内容宽度。
- 企业端指标刷新、会话状态条、解析流水线和评测基线对比均由真实数据驱动。
- 管理端筛选审计事件时只更新结果区，并支持游标加载更早事件。
- 全局支持 `prefers-reduced-motion: reduce`，降低动态偏好下取消位移和循环动画。

## 验证方法

- 后端：在 Conda `rag` 环境运行 `python -m pytest -q`，当前 74 项通过。
- Python 静态检查：运行 Ruff，平台与企业接口、测试和主应用无错误。
- 前端：运行 `npm run typecheck` 和 `npm run build`，TypeScript 与 Vite 生产构建通过。
- 视觉回归：在真实本地服务上逐页访问，桌面使用 1280 x 720，移动使用 390 x 844；16 个页面均无整页横向溢出。
- 数据真实性：Redis、Milvus、Neo4j、Ollama、MCP 和数据库均使用实时探针；租户、审计、文档、模型和评测不使用随机数或静态演示记录。

## 当前边界

- 项目尚无平台级租户目录、计费系统和跨租户配额执行器，因此管理端只展示当前令牌租户；创建租户和调整配额保持禁用。
- 项目尚无 SCIM 目录同步，因此企业成员页只展示 JWT 当前身份和审计窗口内已观测身份；邀请成员保持禁用。
- Ollama 不提供 GPU 显存、QPS 和队列指标，模型页不推测容量；需要接入 GPU Exporter 和指标存储后再启用容量告警。
- 维护操作需要审批、后台任务、结果审计和回滚链路，当前保持禁用，不能直接宣称满足大规模生产控制面要求。
- 当前浏览器验收覆盖主要桌面与移动视口；正式上线前仍需补充多浏览器、键盘全流程、屏幕阅读器和高并发压测。
