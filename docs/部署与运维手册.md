# 部署与运维手册

## 组件

- `api`：FastAPI、SSE、前端静态文件和健康探针。
- `worker`：Redis Streams 消费者，执行解析、切片、入库和删除。
- `mcp`：受 JWT scope 保护的 RAG 检索工具。
- `migrate`：一次性 Alembic migration job。
- `postgres`、`redis`、`milvus`、`neo4j`：业务元数据、checkpoint/队列和检索后端。
- Ollama 默认复用宿主机服务；生产建议使用独立推理服务。

## 发布前

1. `python scripts/secret_scan.py`
2. `python -m pytest`
3. `python -m alembic upgrade head --sql` 审核迁移 SQL。
4. `npm ci && npm run typecheck && npm run build`
5. `docker compose config --quiet`
6. 备份 PostgreSQL、Milvus/MinIO 和 Neo4j，并确认恢复点。
7. 准备 JWT 公钥 secret；生产容器不应持有签名私钥。
8. 配置 `QWEN_API_KEY`、`LLAMA_PARSE_API_KEY`，并通过 `RERANKER_MODEL_HOST_PATH` 只读挂载重排模型。

## 发布

本版本升级了 Redis Streams 任务协议。升级前先停止 API 入队，等待 `rag:jobs` 与 pending 列表清空，再停止旧 Worker、执行迁移并同时发布新 API/Worker。旧消息缺少 `requested_by` 或 `request_id` 时会进入死信，不会使用默认用户绕过审计。

```powershell
docker compose build
docker compose up -d postgres redis etcd minio milvus neo4j
docker compose run --rm migrate
docker compose up -d api worker mcp
docker compose ps
```

验收：

```powershell
Invoke-WebRequest http://127.0.0.1:8080/api/health/live
Invoke-WebRequest http://127.0.0.1:8080/api/health/ready
```

readiness 返回非 200 时不能接入流量。响应只暴露组件布尔状态，详细错误查看结构化日志。

## 监控与告警

- 抓取 `/metrics`。
- 对 HTTP 5xx、P95、Worker `dead_letter`、readiness 失败、Redis Stream backlog 设置告警。
- 日志以 JSON 输出，使用 `X-Request-ID` 串联请求；禁止记录 query、文档正文和访问令牌。
- 监控 `rag:jobs:dead-letter`，修复下游后由运维审核再重放，禁止自动无限重试。

## 安全审计

- 审计接口为 `GET /api/admin/audit-events`，仅授予安全管理员 `audit:read`；查询自动限定 JWT 中的 `tenant_id`。
- 支持按 `action`、`outcome`、`actor_id` 筛选，使用不透明 `cursor` 翻页；单页最多 200 条。
- API 与 Worker 通过 `request_id`、`job_id` 关联请求、重试、死信和最终结果；聊天流分别记录受理与完成/失败。审计元数据不得写入提示词、文档正文、文件名、路径、Cookie 或令牌。
- 客户端 `X-Request-ID` 仅接受 1 到 64 位字母、数字及 `._:-`；无效值会被替换，响应头返回系统实际采用的 ID。
- 已认证用户缺少接口权限时，RBAC 在返回 403 前记录 `authorization.denied`；无有效身份的 401 由入口网关或 IdP 记录。
- PostgreSQL 迁移会创建触发器，拒绝对 `audit_events` 执行 `UPDATE` 和 `DELETE`。数据库超级用户、备份管理员和基础设施管理员仍可能绕过此边界，因此它不是 WORM 证明。
- 生产环境应将审计事件持续导出到企业 SIEM 或启用对象锁的存储，配置保留期、访问告警、时钟同步和完整性校验；定期抽查数据库事件数与归档事件数。

## 会话数据治理

- `conversations`、`conversation_messages` 和 `conversation_feedback` 保存用户可见的问答正文、附件名称、引用和反馈；LangGraph checkpoint 仅用于执行恢复，不能作为展示层消息源。
- 查询必须同时限定 JWT 中的 `tenant_id` 和 `user_id`。安全抽样应覆盖同线程 ID 的跨租户、跨用户访问，预期均为 404。
- 生产 PostgreSQL 应启用磁盘或云数据库静态加密、TLS 传输、最小权限账号和备份加密；数据库日志禁止记录消息正文和访问令牌。
- 上线前由法务、安全和业务共同确定会话保留期、用户删除请求、诉讼保全和备份过期策略；当前版本不内置自动删除策略，不能默认无限期保留。
- 从旧版本升级后，历史审计任务仍显示状态，但没有正文详情；不得从内部 checkpoint 反推并展示系统提示词或工具消息。

## 检索证据与解析预览

- `/api/search` 将结构化证据按 `tenant_id + user_id + evidence_id` 写入 Redis，默认 TTL 为 900 秒；可使用 `RETRIEVAL_EVIDENCE_CACHE_TTL_SECONDS` 调整，但不得设置为无限期。
- `/api/search/evidence/{evidence_id}` 只能读取当前令牌作用域内的缓存；过期或跨用户访问统一返回 404，缓存内容不得写入日志和审计元数据。
- `/api/documents/{document_id}` 在详情读取时重新执行 owner/ACL 授权。响应不包含 `file_path` 或 `file_path_md`，解析预览只允许读取知识库受控解析目录。
- 当前定位粒度为文档、版本和切片；若上线 PDF 页码、坐标高亮或原始文件下载，需要增加短期签名 URL、下载审计和内容安全响应头。

## 备份

- PostgreSQL：每日全量 + WAL/PITR；元数据与任务状态必须一起恢复。
- Milvus：按官方备份工具备份 collection 及 MinIO 对象。
- Neo4j：使用 `neo4j-admin database dump/backup` 对目标数据库执行一致性备份。
- 知识文件：备份 `knowledge_data` volume；多副本生产应迁移到启用版本控制的对象存储。
- 每季度至少执行一次恢复演练，记录恢复耗时和数据校验结果。

## 回滚

1. 从负载均衡摘除新版本 API。
2. 停止新版本 Worker，避免旧代码读取新任务格式。
3. 回滚应用镜像到上一个不可变 tag。
4. 数据库迁移优先采用向前修复。只有迁移明确支持且已验证时，才执行 `alembic downgrade <revision>`。
5. 若数据写入格式不兼容，从发布前恢复点恢复 PostgreSQL 和检索后端；不要只恢复一个后端。
6. 恢复流量前验证 readiness、租户隔离抽样、上传/检索/删除链路。

## Worker 故障

- 单次失败：任务以相同 job ID 重新入队，attempts 增加。
- 重试耗尽：任务和文档标记失败，消息写入 `rag:jobs:dead-letter`。
- 双写部分成功：任务失败且保留后端状态；稳定节点 ID 使重试可幂等覆盖。
- 删除失败：不删除本地文件和元数据，避免出现无法追踪的后端残留。

## 扩容约束

- API 可以水平扩容，checkpoint 与限流依赖 Redis。
- Worker 可增加 consumer；发布期间不同版本 Worker 不应并存处理同一协议。
- 当前知识文件使用共享 volume。未接对象存储前，不支持无共享盘的多节点 API/Worker。
- Neo4j 图抽取和 reranker 资源消耗大，应独立设置并发和资源配额。
