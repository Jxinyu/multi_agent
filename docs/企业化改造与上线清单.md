# 企业化改造与上线清单

日期：2026-07-18

## 结论

本轮已将项目从“可演示原型”提升为“可进行受控试点的企业工程基线”。认证、租户隔离、异步入库、失败语义、迁移、测试和交付链路已有代码证据，但它仍不等于完成正式生产验收。正式上线还依赖企业 IdP、密钥轮换、TLS、备份演练、容量压测和真实业务数据验收。

## 已完成

| 风险 | 改造结果 | 验证方式 |

| 任意大文件和伪扩展名 | 流式大小限制、文件数限制、签名检查、分片大小/顺序校验、安全路径 | 存储边界测试 |

| 查询和令牌泄漏 | 去除查询内容日志；前端令牌仅在内存；聊天记录不持久化到浏览器 | 静态扫描与前端构建 |

## 上线门槛

以下事项不能由仓库代码替企业环境做决定，正式生产前必须完成：

1. 接入企业 IdP 的 Authorization Code + PKCE，配置 `AUTH_MODE=oidc`、issuer、audience 和 JWKS；关闭开发令牌。
2. 吊销历史中出现过的 API Key、数据库口令和 JWT 私钥；清洗 Git 历史后复核 GitHub 缓存与 fork。
3. 在 ingress/service mesh 启用 TLS、HSTS、请求体上限和 WAF；内部 Redis、PostgreSQL、Milvus、Neo4j 使用私网与独立账号。
4. 配置 PostgreSQL PITR、Neo4j/Milvus/MinIO 备份；执行恢复演练并记录 RPO/RTO。
5. 使用企业文档做 ACL 对抗测试、提示注入测试、恶意文件扫描和人工答案验收。
6. 执行容量压测，覆盖 SSE 长连接、并发检索、图谱抽取、Worker 堆积、外部模型超时和下游熔断。
7. 配置 Prometheus 告警、日志集中存储和审计保留周期；当前代码只提供结构化运行日志与指标基线。
8. 若 API 多副本部署，将本地知识文件卷替换为 S3/MinIO 对象存储；当前共享 volume 方案更适合单机受控试点。

## 量化指标边界

- 路由 `+19.60%` 的主集是脚本构造的 120 条企业样本，CLINC150 只做公开补充，不应描述成全部公开企业基准。
- 检索 `+22.34%` 来自 MultiHop-RAG holdout 上的监督式 LambdaMART 实验；运行时双路 RAG 目前使用稳定去重融合，不会自动复现该数字。
- 解析 `+49.99%` 来自可复现控制样本；PubTables 公开样本应写“达到 86.94%”，不写相对倍数。
- 成本从 30 次到 0 次只代表云解析调用次数代理指标，不代表账单金额下降 100%。

## 企业可用性判断

- 本地演示：可用。
- 单租户或少量租户受控试点：满足基础工程条件，完成 IdP、密钥和备份后可进入验收。
- 多区域、高合规、大规模正式生产：尚未完成，主要缺口是对象存储、灾备、审计平台、压测和企业安全体系接入。
